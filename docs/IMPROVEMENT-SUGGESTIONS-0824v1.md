# Codex Account Manager Next 0824v1 — 改进建议单

> 2026-08-24 由 Claude 基于源码审查生成。仅是建议，逐条独立评估，不必都采纳。
> 优先级排序依据：风险消除 > 可维护性 > 易用性 > 锦上添花。

## P0 · 上线前必须做（不是改进，是补课）

### 1. 真实环境端到端验证自动切换
- **现状**：HANDOFF 记录所有验证均为逻辑自测（20 项通过），从未用真实账号执行过一次完整自动切换。
- **为什么排第一**：自动切换会替换 `~/.codex/auth.json` 并重启 Codex，属于全项目风险最高的路径。逻辑测试再全也覆盖不了真实 app-server 行为、Keychain、进程退出时序。
- **建议动作**：准备两个测试账号 + 测试 webhook，手动把触发条件凑齐（或临时调低阈值编译一个调试包），完整跑通"触发→验证→切换→恢复→通知"一次；失败场景至少各演练一次。

## P1 · 强烈建议

### 2. 给自动切换加低频兜底定时器
- **现状**：`evaluateAutomaticAccountSwitch()` 是事件驱动——只在任务快照更新、手动刷新等时机触发，没有周期性巡逻。
- **风险**：用户离开电脑后若恰好无新事件触发快照刷新，额度跌破 10% 可能迟迟不评估。而"人不在场"恰是自动切换的核心使用场景。
- **建议动作**：功能开启时挂一个 3–5 分钟的低频 Timer 兜底调用评估函数；已有冷却/锁/门禁保护，多调几次不会误切。

### 3. 拆分 main.swift（13967 行）
- **现状**：账号切换、额度刷新、任务监控、UI 状态几乎全部堆在 main.swift，本次新增代码继续向该文件堆积。
- **代价**：每次修改都在巨型文件里定位，改 A 容易碰坏 B；diff 审查困难。
- **建议动作**：纯搬家不改逻辑。优先拆出：AccountSwitchController、QuotaRefreshEngine、TaskMonitorStore 三块，每拆一块跑一遍全部 self-test 再拆下一块。

## P2 · 建议

### 4. 自检代码移出正式包
- **现状**：`CodexAutomaticSwitchPolicySelfTest` 等自测枚举与产品代码同编译单元，随 App 发布。
- **建议动作**：建独立 test target（XCTest 或 Swift Testing），self-test 逐步迁移过去。过渡期可保留现有 CLI 入口作为冒烟测试。

### 5. 阈值与冷却参数开放到设置页
- **现状**：10% 触发线、30% 候选线、30 分钟成功冷却、1 小时失败重试均为硬编码常量。
- **建议动作**：进自动化中心设置页，给出合理范围限制（如触发线 5–25%）+ 默认值标注"已按安全标准校准"。个人使用可缓，做分发前建议做。

### 6. 补 macOS 原生通知通道
- **现状**：结果通知仅飞书 Webhook 一条路。
- **建议动作**：增加 NSUserNotification/UserNotifications 作为默认通知方式，飞书保留为远程场景选项。成本低。

## P3 · 记录在案，暂不建议动

### 7. 跨版本并发竞态
旧版不共享 Next 的锁，文档已如实披露并靠"检测旧版进程即拒绝"缓解。彻底解决需要两版共享锁协议，但既然方向是淘汰旧版，投入产出比低——删干净旧版即是解。

### 8. UI 层
界面无已知问题，本次不建议动。自动化中心后续加配置项时顺带迭代即可。

# Next 设计与交互规范

当前基线为 0905v3。Next 面向两类人，一类只想看清自己的额度并开始工作，另一类需要管理多个隔离账号和任务占用。界面围绕这两个真实流程组织。

## 产品识别

- 产品名称使用 Codex Account Manager Next，短称 Next，页头可用 NEXT 字标。
- 默认蓝紫强调色表达模型、选中项与主要入口，配色切换继续使用现有语义 Token。
- 不使用其他账号管理软件的社区入口、宣传图、产品口号或页面布局作为 Next 的展示材料。
- 开源版权与许可集中记录在适用声明中，保留依法需要的来源信息，不用品牌设计覆盖许可义务。

## 工作台

- 单账号首屏优先显示额度、重置时间、模型与终端入口，统计和高级管理按需展开。
- 多账号展示同一套字段与安全状态，支持账号备注、排序与逐个操作。
- 系统入口与隔离入口按身份去重，不为了展示批量操作虚增账号数。
- 账号卡直接呈现刷新异常和任务状态，不增加重复的巡检页面。
- 当前额度与累计 Token 分开，官方值、本地值与费用估算分开。
- 窄窗口允许卡片内容重排，但不随宽度连续缩放字体。

## 设置

- 外观、菜单栏、自动化、工作区、关于五个分区始终直达，不藏在同名二级菜单中。
- 主题用可点击的预览卡展示；少量互斥选项使用原生分段控件；大量有意义的选项可以使用原生菜单。
- 模型与思考强度点击后直接出现选项，不先出现“模型”或“强度”入口。
- 菜单栏预览与实际状态栏共享展示模型，恢复默认放在预览旁。
- 暖号按 5 小时和 7 天窗口分开，旁边说明额度消耗与忙碌保护。
- 设置标题、简短说明与控件层次分明；长说明使用整行宽度，不挤在控件左边。
- 页脚保留打开工作台与退出，避免用大面积主按钮抢走设置控件的注意力。

## 视觉与动效

- 使用 SwiftUI/AppKit、系统字体与 SF Symbols，优先复用已有组件。
- 表面保持清晰的浅深对比，材质不能牺牲文字可读性；避免重卡片套卡片。
- Accent、Status、Data、Surface 各自承担语义，配色不能改变危险或成功的含义。
- 数字使用等宽显示；状态必须有文字或图标，不能只靠颜色。
- 高频选择立即响应，不添加阻碍操作的过渡动画。
- 额度粒子只在既有前台、聚焦和省电规则允许时显示，尊重低电量、温控与减少动态效果。
- 隐藏、最小化、失焦时停止不必要的逐帧重绘；后台维护与前台视觉刷新分开。

## 数据与安全文案

- 未知、缺失、过期、失败与真实零值保持区别。
- 忙碌或状态不可信时，说明入口不可用的原因；不能把未知包装为空闲。
- 模型可选不等于账号已获服务端访问资格，不做静默降级承诺。
- 暖号会消耗额度，不承诺增加额度、保证新窗口启动或解除周限制。
- 低额度候选提示不称为自动派单或自动切号。
- 不展示凭据、Webhook、任务正文、原始日志或私人路径。

## 发布图与回归

- 公开图统一使用生产组件加隔离演示数据，保留原始 2× PNG，不把放大图称为原生高清图。
- 文件按序号、产品、内容、语言与明暗命名，尺寸与校验和写入素材索引。
- 检查浅深主题、中英文、长文案、键盘、可访问性、空状态与失败状态。
- 原生预览、纯测试和实际弹窗点击分别记录，不能以一项代替另一项。
- 配色包的稳定 ID、安全约束与字段要求继续遵循 [Palette Package 契约](PALETTE_PACKAGES.md)。

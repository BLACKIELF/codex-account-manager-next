macOS / Windows 架构对齐审查

2026-07-28 · 只读代码与架构文档审查 · 非运行时或视觉验收

结论：Windows 目前是 Codex-first 的局部重建，不是 macOS 架构的等价实现。

Claude Code 暂不在 Windows 范围内；本审查不要求补做它。macOS 的核心是保留 runtime 输入边界，再统一编排、任务归一与领导力证据评分。Windows 当前可以只做 Codex，但它把结果压成一个 LocalUsage，并在同一聚合函数中推导 leadership，再经 Tauri 交给 React。复制了同名模型和页面，却没有接通相同的责任边界。

两条真实数据流

macOS 中真正值得迁移的块

块责任为何可迁移
Runtime Provider每个 runtime 输出独立的 snapshot、状态与来源。是平台无关的产品语义边界，不是 SwiftUI 细节。
Multi-runtime 编排先取得每个 runtime，再产生 aggregate。避免合并后丢失 Codex / Claude 的可用性与错误信息。
领导力 evidence pipeline从 worker / interval / quality 形成评分输入，并带缓存。使“缺证据”可表达为未评分，而不是伪造分数。
消费者分离主窗口与状态栏消费各自需要的 snapshot。Windows tray 可以有自己的原生实现，但应消费同一合同。

Windows 的关键偏离

优先级事实架构后果
P0Tauri AppState 只装配 Codex reader，并缓存 / 返回 LocalUsage。Codex-only 是当前范围；问题是顶层合同仍丢失 runtime 可用性、来源标签、配额与 task-board 等 Codex 自身语义。
P0用量聚合与 leadership snapshot 在 make_local_usage 同时生成。Reader、聚合器和评分器坍缩；即使只做 Codex，也难以独立测试、校准或说明语义。
P0Windows leadership 从 token event、tool-call 比率与固定启发式推导，并总是返回 score。与 macOS 的 interval / evidence-quality / null-score 门槛不同；不能把相同等级标签视为同义。
P1Rust 定义了 MultiRuntime 类型，Claude reader 也存在，但 Tauri app 未接线。Claude 未接线是有意的范围控制；即使只启用 Codex，也应先接入单 runtime snapshot，而不是误称已经对齐。
P1Dashboard 标注 Local only，Tasks 与 Skills 显示无合同的空态。降级文案是诚实的，但说明页面外观不能代表功能 parity。
P1Windows tray 只提供 Open / Settings / Refresh / Quit。它是窗口入口，尚非 macOS status-item 的快速扫描 consumer。

推荐的 Windows 目标边界

不要继续翻译 macOS UI；让 Windows 重回同一套责任顺序。 
Windows Codex local sources / app-server
  → Codex platform adapter (only enabled provider)
  → RuntimeUsageSnapshot boundary
  → local usage | task normalization | quota continuity
  → leadership evidence reader/cache → macOS-aligned scoring semantics
  → CodexDashboardSnapshot IPC → Tauri state → React dashboard / tray

LocalUsage 应退回为单一 runtime 的本地用量子对象；当前顶层 IPC 至少需要 Codex snapshot、leadership、刷新时间与可解释的降级状态。不要为 Claude 提前实现聚合或 UI。

建议的重建顺序

  1. 更正 Windows 蓝图：将当前“从 macOS 直接迁移”的图标为目标草案，而非实现真值。
  2. 先接 Codex provider seam：输出明确的 runtime snapshot 与状态，不接入 Claude reader。
  3. 从 usage 聚合中拆出 leadership evidence / scoring；未完成语义移植前，结果必须标作估算，不可复用权威等级文案。
  4. 把 Tauri IPC 与缓存升级为 Codex dashboard contract。
  5. 最后绑定 Dashboard、空态和 tray，再做 Windows 原生视觉验收。

Windows UI Parity Report: Dashboard Home Alignment

Report date: 2026-07-28. Verdict: accepted for page-level Dashboard hierarchy at the compact desktop target. This is not a pixel-perfect or numeric-parity claim.

Scope: Windows Dashboard hierarchy, lower-panel restoration, native visual evidence, and retained data-contract boundaries.

Acceptance conclusion

  • The final native default Dashboard shows three horizontal top groups: Leadership, local 7-day Token mix, and Today / 7-day / Lifetime summaries.
  • Input, Cached input, and Output are shown once each in the fixed top's 7-day Token mix; visual inspection found no duplicated count. The fixed top contains no raw thread, project, or tool content.
  • At the target compact viewport, the complete L1-L7 rail is visible: title, badges, bar, and labels are not clipped.
  • AI Leadership detail preserves the information hierarchy of the macOS reference: identity, score/facts, and command rail. Windows keeps light/system Liquid Glass styling rather than copying macOS pixels.
  • The lower area exposes Tasks, Usage, Projects, and Skills. Tasks and Skills are complete honest empty shells with data contracts still blocked; Usage and Projects are real local-data panels with partial semantic parity.

Native evidence

All six images come from final windows/target/release/codexu-tauri.exe. Capture used PrintWindow against the target HWND, not Computer Use. Default DWM bounds were 1439x1136 physical pixels and the remaining batch was 1440x1137; DPI 144 yields approximately 960x758 CSS pixels. Both are within one physical pixel of the compact target. The exact target release process was cleaned up after capture (zero matching processes remained).

The Tasks, Usage, Projects, and Skills captures were taken after scrolling to the lower tablist. They evidence those tab panels, not a claim that the lower panels are in the first screen.

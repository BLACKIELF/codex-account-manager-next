CODEX Dashboard Snapshot Refactor Design

Status: implemented and accepted for the Codex-only Windows Dashboard contract. Date: 2026-07-28.

Scope: one local Codex snapshot pipeline for Tauri; no Claude provider, selector, or synthetic quota surface.

Design outcome

local Codex state_5.sqlite + local rollout/session JSONL
  -> CodexDashboardProvider
  -> CodexDashboardSnapshot
  -> source-keyed, single-flight AppState cache + Tauri IPC
  -> web useUsage() + Dashboard consumers

CodexDashboardProvider is the only enabled provider. It reads local state metadata and cached local session summaries, then creates independent local-usage and leadership branches before assembling one snapshot.

Contract boundary

CodexDashboardSnapshot {
  codex: RuntimeUsageSnapshot,
  leadership: CodexLeadershipSignal,
  refreshed_at,
  messages,
}
  • codex is RuntimeScope::Codex / local-only; local metrics remain nested at codex.snapshot.local.
  • Official quota is unavailable: quota fields remain absent and the UI must not invent quota, allowance, remaining balance, or billing values.
  • AppState refreshes are source-keyed, generation-checked, and single-flight. Provider warnings are source-safe and do not expose state paths or database diagnostics.
  • Generic runtime types do not enable Claude: there is no active Claude provider or selector in this Dashboard.

Leadership integrity

Leadership is independent from local token aggregation. Transcript parsing preserves task intervals; the leadership report computes dimensions, coverage, active-day count, maturity, score, and title.

  • Score visibility requires four dimensions, positive active days, coverage at least 0.70, and a non-stub model.
  • Maturity prevents an unwarranted perfect score before 28 active days or weak coverage.
  • Without a valid report score, leadership.score is null and UI consumers render an insufficient/pending state. Title comes from the selected-period report, not a UI heuristic.

Native evidence and validation

Accepted final release evidence is non-Computer-Use HWND PrintWindow capture at 1462x1196 physical pixels / DPI 144, approximately 975x797 CSS px.

  • Default Dashboard: three global tabs, full L1-L7 rail, and 1,784,569,471 + 1,706,410,112 + 9,142,958 = 3,500,122,541 Token mix with no raw body content.
  • AI Leadership: identity, score, rail, and metrics in the detail hierarchy.
  • Lower Dashboard navigation: pure Win32 SendInput PageDown plus wheel scrolling, then PW_RENDERFULLCONTENT, shows readable L1-L7, local API-equivalent Month value / not official quota, and one Tasks / Usage / Projects / Skills tab bar. It proves navigation hierarchy only, not variable-panel internals or strict cross-platform equivalence.

Non-goals

  • No Claude runtime implementation or selector.
  • No official quota reader, fake quota, points change, or remote service.
  • No claim that a local Month estimate is strict macOS Wool equivalence.

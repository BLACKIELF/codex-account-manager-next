Windows Dashboard Home Design

Approved direction · 2026-07-27 · Windows Tauri presentation layer and static showcase only

Create a real high-density Dashboard with the macOS reference's hierarchy: leadership identity, an honest usage focus, key summaries, progression, and trends. It is not a dark promotional clone.

Data boundary

The active Windows commands expose local Token usage and Leadership data, but not official quota/rate-limit responses. This design does not add readers, cache behavior, IPC fields, estimates, or fake quota percentages.

Desktop hierarchy

Leadership identity
Command-radius summary and four honest 28-day metrics.
Seven-day Token focus
Local Token total and input/cached/output composition; never framed as account allowance.
Usage summaries
Today, seven-day, and Lifetime totals.
Leadership progression
Existing L1–L7 badge assets at 0/20/35/50/65/80/93; full 0–100 semantic gradient clipped at the actual score.
Seven-day bars
Existing real daily Token series.
Long-range trend
Existing range-switching usage trend and exact tooltip values.

Product surface, not a mockup

  • Dashboard becomes the default tab. Leadership remains its own detailed tab; Usage, Threads, and Projects remain dedicated views.
  • All data comes from the existing local usage snapshot. No prompt, response, raw log, path, or account data is introduced.
  • After native acceptance, a Markdown and HTML showcase will use only real final screenshots and will state retained Windows/macOS differences.

Acceptance

  • Readable without clipping at an approximately 960×760 native window.
  • npm run build, cargo test --workspace, cargo tauri build --no-bundle, and git diff --check pass.
  • Visual review proves the hierarchy, rail mapping, truthful usage labels, and retained platform differences.

# Windows UI 移植执行计划（Phase 4）

**目标**：按 macOS 体验优先推进 Windows Tauri UI，优先实现可用的交互闭环，再做视觉精修，最后做发布前验收。

## 全局规则（Mac 迁移约束）

- 先保证交互闭环可用：状态、加载、失败、空状态、Tab 切换、刷新都要可用。
- 视觉在行为稳定后再做精修。
- 保留本地优先与隐私优先原则，不上传用户使用原始数据。
- 每完成一个 Phase 做一次 review，列明证据、风险、回退点。

## Phase 1：数据闭环（Data Pipe）

### 目标

- 把 AI 领导力数据从 `core` 一路打通到 Tauri 前端可用模型。

### 要求

1. 后端/内核：
   - 领导力摘要数据能在 Rust core 中形成稳定结构。
   - 领导力模型与 usage 数据的 `AppState` 共享与缓存策略一致。

2. Tauri 命令层：
   - `get_local_usage` / `refresh_usage` 返回前端可消费的字段（先做可为空 `null` 兜底）。

3. Web 结构：
   - `types/models.ts` 增加领导力数据类型。
   - `hooks/useUsage.ts` 同步解析新字段。

### 完成标准

- `Dashboard` 可以读到 `leadership` 字段，不因字段缺失导致渲染错误。
- 失败状态有可恢复提示，不影响用量/任务区块。

## Phase 2：主 UI 结构重建（Mac 交互优先）

### 目标

- 先把 mac 的“页面结构+交互关系”对齐出来，再做视觉细节。

### 要求

1. Tab 结构与入口：
   - 提供 `任务`、`AI 领导力`、`用量`、`项目` 这四类主入口。
   - 切换即时生效，不出现明显空白跳变。

2. 内容分发：
   - 各 tab 渲染与主内容解耦（可在不影响其他模块的前提下迭代）。

3. 状态与反馈：
   - 刷新、加载、错误、空状态统一提示；支持 Retry。

4. 可访问性与键鼠：
   - tab 键焦点、aria 标记、按钮可操作性达成最小可达标准。

### 完成标准

- 可稳定切换 4 个 tab，当前视图与 mac 行为优先一致（先行为后样式）。
- 所有 Tab 都有明确错误/空态文案，不出现卡死或白屏。

## Phase 3：详情与视觉打磨（Leadership 深化）

### 目标

- 在阶段 1/2 稳定后，补齐 AI 领导力详情与展示一致性。

### 要求

1. 领导力入口：
   - 总览卡 + 详情入口可达。

2. 指标展示：
   - 总分、Title、四维度、近 28 天 Agent/AI 工时/峰值并发、项目贡献。

3. 时序展示：
   - 28 天曲线/分组卡片布局符合数据可读优先。

4. 样式对齐：
   - 参照 `docs/DESIGN_SYSTEM.md` 逐条核对卡片、色彩、间距、tooltip 与文案层级。

### 完成标准

- 领导力详情页可直接从主页面到达且交互可用。
- 关键指标不出现未定义/错误拼接文案。

## Phase 4：兼容、回归与验收（Delivery）

### 目标

- 全量验证行为与可发布性。

### 要求

1. 功能回归：
   - 用量、任务、项目、领导力四模块都可用。

2. 体验对齐：
   - `dashboard` 的跳转、刷新、错误提示、焦点行为与 mac 风格优先级一致。

3. 证据留存：
   - 每个 phase 记录检查证据（命令输出 / 截图 / 问题清单）。

### 完成标准

- 关键路径可演示（启动、刷新、切换、查看 leadership 详情）。
- 无关键回归（UI 卡死、空白页、数据崩溃）。
